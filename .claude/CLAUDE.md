# Pnewmo

Каталог промышленного оборудования: гидравлика, пневматика, вакуумная техника.
Русскоязычный B2B-магазин. Домен вращается вокруг товара, категории образуют дерево
глубиной до пяти уровней.

## Структура

```
apps/web               Next.js: витрина, служебный роут /dev
apps/api               NestJS: HTTP API
packages/api-contract  ts-rest + Zod: единственный источник правды об API
```

Контракт валидирует запросы на сервере и типизирует клиент одной и той же схемой.
Опечатка в имени поля ломает `pnpm typecheck`, а не проявляется в рантайме.

## Стек

Node 24 · pnpm 10 · Turborepo 2 · Next 16 (Turbopack) · NestJS 11 · Prisma 7 ·
PostgreSQL 16 · ts-rest 3.52 · Zod 3 · TypeScript 5.9 · Jest 30

## Жёсткие ограничения

Каждое стоило времени. Нарушение любого приводит к неверному шагу с первой попытки.

1. **Node 24.** Node 20 в EOL с 30 апреля 2026. Версия в `.nvmrc`, сначала `nvm use`.
2. **Prisma 7, не 6.** Генератор называется `prisma-client`, `output` обязателен,
   рантайм требует драйвер-адаптера: `new PrismaClient({ adapter })` вокруг `pg.Pool`.
   `datasourceUrl` не работает. Примеры для шестой версии из интернета не заведутся.
3. **Zod пинится на 3.x.** ts-rest 3.52.1 требует `zod ^3.22.3`; поддержка Zod 4 есть
   только в нестабильной `3.53.0-rc`.
4. **TypeScript пинится на 5.x.** В реестре latest — `typescript@7`, но Next 16 и
   Nest 11 собраны против 5.x.
5. **Push не выполняется.** `origin` указывает на репозиторий тимлида
   `NazarJS/Pnewmo-next`. Работа живёт в локальной ветке `dev`.
6. **`pnpm lint` завершается с кодом 1** — это зафиксированный baseline, а не поломка:
   2 ошибки eslint и 21 stylelint в существующем коде фронтенда, унаследованные до
   перестройки в монорепо. Полный список — в спеке этапа 1, раздел «Baseline линтеров».
   Пакеты `@pnewmo/api` и `@pnewmo/api-contract` обязаны линтоваться **чисто**.

## Состояние

Готово: монорепо и инфраструктура, таблицы `categories` и `products` с полным CRUD,
сиды на 222 категории и 4842 товара, единая форма ошибок.

Дальше: этап 4b — перевод витрины с `json-server` на реальный API: слой TanStack Query,
страница `/admin`, карточки и пагинация товаров.

Фронтенд пока читает каталог из `apps/web/db.json` через `json-server` на порту 3001.
Категория, созданная через API, попадёт в меню, но страница каталога о ней не знает —
это ожидаемое переходное состояние.
