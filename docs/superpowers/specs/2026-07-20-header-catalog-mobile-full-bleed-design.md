# HeaderCatalog: убрать боковые отступы у .catalog_container на мобильных ширинах

## Контекст

`src/widgets/header/ui/header-panel/header-catalog/HeaderCatalog.module.scss`, `.catalog_container` внутри `@include xs` (`≤1024px`, `_breakpoints.scss`) сейчас имеет `left: 0; width: 100%`, что считается от `.header_panel_main` — родителя, вложенного в глобальный `.container` (`globals.scss`). На мобильных ширинах видны равные отступы слева и справа между краем viewport и серым фоном каталога.

Похожая задача уже решалась для десктопа (см. `2026-07-20-header-catalog-multi-accordion-design.md` и более раннюю работу над `.sidebar::after`) — там была асимметрия (только левый край до края viewport, правый остаётся как есть) и сложность из-за `max-width: 1440px` у `.container`. Здесь задача проще.

## Анализ (проверено в коде)

- `.catalog_container` — `position: absolute`, containing block — `.header_panel_main` (`position: relative`), которая является padding-box'ом `.container`.
- `.container` в `globals.scss` имеет `max-width: 1440px` и `padding: 0 40px`, с дублирующимся `@media (width <= 1024px)` (первый блок `24px`, второй `16px` — второй перебивает первый; этот баг ранее сознательно оставлен как есть, не в рамках текущей задачи).
- На мобильных/планшетных ширинах (`≤1024px`) `.container`'s `max-width: 1440px` никогда не ограничивает ширину — вьюпорт всегда меньше — поэтому центрирующего зазора (как на десктопе) нет. Единственный источник отступа — сам `padding` контейнера, который на этих ширинах равен `16px` с каждой стороны (за счёт дублирующегося media-блока выше).
- Следовательно, в отличие от десктопного случая, здесь не нужна `vw`/`min()`-математика — достаточно скомпенсировать фиксированные `16px` с обеих сторон.

## Дизайн

Внутри `@include xs`-блока `.catalog_container`:

```scss
@include xs {
  left: -16px;
  width: calc(100% + 32px);
  // остальные существующие свойства без изменений
}
```

`16px` дублирует текущее эффективное значение padding `.container` на этих ширинах (см. Анализ). Значение захардкожено умышленно (как и `40px` в десктопном `$catalog-left-shift`) — общей SCSS-переменной для padding контейнера пока нет. Если padding в `globals.scss` изменится, это значение нужно будет синхронизировать вручную — помечаю комментарием в коде.

Никакие другие свойства/файлы не трогаем — `.mobile_catalog`, `.container_catalog`, десктопный `.sidebar::after`, скролл-фикс (`height`/`overflow-y`/`min-height`) не затрагиваются.

## Тестирование / проверка

Ручная проверка в браузере на ширинах `≤1024px`: открыть каталог через мобильный/планшетный триггер, убедиться что серый фон `.catalog_container` доходит до обоих краёв viewport без зазоров, и что при этом список категорий и accordion не сдвинулись и не деформировались.

## Вне объёма задачи

- Дублирующийся `@media (width <= 1024px)` в `globals.scss` — не трогаем (решение принято ранее).
- Десктопное поведение (`.sidebar::after`, `$catalog-left-shift`) — не затрагивается.
